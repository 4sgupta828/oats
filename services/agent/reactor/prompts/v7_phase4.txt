## Phase 4: CAUSAL_CONFIRMATION (Your Current Phase)

**Objective:** Ensure your suspected root cause is the **source**, not a **victim** of an upstream failure.

Before declaring victory, you must validate: "Is this component's failure caused by something else?"

---

## The Victim vs. Source Problem

**Example Scenario:**
- You identified: "database-1 is experiencing slow queries (root cause)"
- But what if: storage-volume-xyz has disk IO degradation?
- Reality: database-1 is a **victim**, storage-volume-xyz is the **source**

**This phase prevents premature conclusions.**

---

## Required Actions

### 1. Get Dependencies

**`get_service_dependencies(service_name, data_dir)`**
- Returns: List of components that `service_name` depends on
- Purpose: Identify all upstream dependencies that could cause failure

### 2. Validate Each Dependency

For **each dependency** returned:

**`check_dependency_health(source_component, target_component, time_window, data_dir)`**
- Returns: connectivity, latency_ms, error_rate, circuit_breaker_state
- Purpose: Check if dependency was healthy during incident

**Alternative (component-specific):**
- `check_instance_health(dependency, time_window, data_dir)` — For infrastructure components
- `get_database_stats(dependency, time_window, data_dir)` — For database dependencies
- `get_cache_stats(dependency, time_window, data_dir)` — For cache dependencies

---

## Decision Logic

**For each dependency checked:**

### Case 1: Dependency Healthy
- ✓ Connectivity normal
- ✓ Latency within baseline
- ✓ Error rate normal
- **Action:** Continue checking remaining dependencies

### Case 2: Dependency Unhealthy
- ✗ Connectivity issues, high latency, or high error rate
- **This is critical:** Your "root cause" is actually a victim
- **Action:**
  - The unhealthy dependency becomes the **new suspect**
  - Update `state.active.phase = "EVIDENCE_GATHERING"`
  - Create new hypothesis for the dependency
  - In `strategize.reasoning`: "Discovered dependency [X] is unhealthy. Suspected root cause [Y] is actually a victim. Pivoting investigation to [X]."

### Case 3: All Dependencies Healthy
- ✓ All dependencies validated as healthy
- **Conclusion:** Your suspect is the **source**, not a victim
- **Action:** Transition to Phase 5 for synthesis

---

## Phase Transition

**Exit Criteria (Promotion to Phase 5):**
✓ All dependencies of suspected root cause validated as healthy
✓ No upstream components could have caused this failure
✓ You can confidently state: "This component's failure was not caused by an upstream issue"

**When criteria met:**
- Update `state.active.phase = "SYNTHESIS"`
- In `strategize.reasoning`: "All dependencies of [component] validated as healthy. Confirmed this is the root cause, not a victim. Transitioning to Phase 5 for complete causal chain synthesis."

**Pivot Criteria (Return to Phase 2):**
✓ Found an unhealthy dependency
✓ The suspected root cause is actually a victim

**When pivot needed:**
- Update `state.active.phase = "EVIDENCE_GATHERING"`
- Create new hypothesis targeting the unhealthy dependency
- Update `state.diagnosis.competingHypotheses` with new suspect
- In `strategize.reasoning`: "Dependency [X] unhealthy. [Suspected root cause] is victim. New hypothesis: H[N] targeting [X]."

## Common Mistakes

**Mistake 1: Skipping dependency validation**
- Always check dependencies before declaring root cause
- A component can fail due to upstream issues

**Mistake 2: Not pivoting when dependency unhealthy**
- If you find an unhealthy dependency, that's the new suspect
- Don't ignore it and proceed to synthesis

**Mistake 3: Shallow dependency checking**
- Check all dependencies, not just the obvious ones
- Use get_service_dependencies() to get complete list

**Mistake 4: Declaring victory prematurely**
- Phase 4 is mandatory before Phase 5
- Even if you're confident, validate dependencies
